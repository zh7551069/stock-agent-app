# stock-advice-agent

> 本目录是 Flask BFF。仓库怎么启动、硬约束、第一切片（5min append / 持仓股 / suggest+confirm）见仓库根 [README](../../README.md)。
> 契约在 `docs/contracts/`，交付说明在 `docs/delivery/`。先手分公式与权重不在本目录改。

> 从 Obsidian 选股知识库 → 可执行策略 → 按「盘前 / 盘中 / 盘后」给出股票推荐。
> 纯本地运行：Flask + DuckDB/pandas，无外部服务、无 CDN 依赖。
> **界面形态：移动端 App（PWA）**，暗色高密度数据界面，可「添加到主屏幕」全屏运行。

## 一、它做了什么

```
Obsidian 知识库（2238 张知识点卡）
        │  ① ingest/build_cards.py
        │     按 `> 诉求：` 与关键词，抽出「选股相关」557 张
        │     并判定时段（盘前 / 盘中 / 盘后）
        ▼
   data/cards.json  ──────────────┐
        │  ② ingest/build_registry.py
        │     27 张可执行卡片 → 27 条策略（含参数、实现 id）
        ▼                         │
   data/strategies.json           │
        │  ③ core/engine.py       │
        │     每条策略 = 一个可计算函数（严格无未来函数）
        ▼                         │
   本地行情库（淘宝 DuckDB）       │
        │  ④ ingest/build_cache.py
        │     日线 320 日 + 5min 12 日 + 涨停池/龙虎榜/资金流
        ▼                         │
   data/cache/*.parquet           │
        │  ⑤ core/recommend.py
        │     三时段聚合打分（多策略共振加权）
        ▼                         │
   server.py（Flask + 静态前端）◄──┘
        │
        ▼
   http://127.0.0.1:8770
```

**三个时段的口径**（页面上也会标注）：

| 时段 | 数据时点 | 推荐含义 | 策略数 |
|---|---|---|---|
| 🌅 盘前 | 上一交易日收盘 | **下一交易日开盘前**的条件单候选：昨日涨停梯队、首板次日高开 4~6%、主线板块龙头、昨日尾盘拉升、竞价结构 | 6 |
| 📊 盘中 | **实时行情**（腾讯 qt 主源 / 东财 push2 备源，20s 缓存）+ 当日分时序列 | 按**实时**快照 + 当日 5min K 线触发：站上均价线、放量突破、涨速、10 点前首触涨停、炸板回封、尾盘强势、板块资金流 | 8 |
| 🌙 盘后 | 最近交易日收盘 | 收盘选股池：RS≥80 领军、带柄茶杯、55 日新高、箱体/窄幅区间突破、缩量回踩、资金回流、60 日低位、行业轮动、短期反转、量价背离预警 | 13 |

## 二、快速开始

```bash
cd stock-advice-agent

# 1) 扫知识库（只读，约 1s）
python3 ingest/build_cards.py          # → data/cards.json（557 张选股卡）

# 2) 生成策略注册表（约 0.2s）
python3 ingest/build_registry.py       # → data/strategies.json（27 条）

# 3) 行情 ETL（需要外盘 My PSSD 已挂载，约 40s）
python3 ingest/build_cache.py          # → data/cache/*.parquet（约 350MB）

# 4) 启动网站
python3 server.py                       # → http://127.0.0.1:8770
```

> 外盘未挂载 / 被数据同步任务写锁时，ETL 会重试并在仍失败时保留旧缓存；
> 网站只读缓存，因此**行情库不可用时网站照常打开**（显示上次快照）。

### 盘中实时行情（v1.2 → v1.6 多源 + 走势）

「盘中」读**实时行情**（交易时段内 20s 快照缓存）。**v1.6 起多源**：腾讯 `qt.gtimg.cn` 为主源、东财 `push2` 为备源、
两者都失败才用最近一次成功快照（标注 stale）。原因：东财 push2 接口在部分网络环境会被直接 `RemoteDisconnected`，
旧版只有东财一个源，于是整天静默回退到历史回放——排行榜看起来"全是历史数据"。

| 数据 | 来源 / 口径 | 用在哪 |
|---|---|---|
| 全市场快照 | **腾讯 `qt.gtimg.cn`**（400 只/请求、15 请求并发、实测 0.68s / 5563 只）；备源东财 clist | 现价、涨跌幅、开高低、昨收、量比、成交额、流通市值、**均价线**、**涨停/跌停价** |
| 分时均价 VWAP | 腾讯快照自带「均价」；东财源按 `成交额÷(成交量×100)` 现算 | 站上均价线、龙头回踩 |
| 当日 5min K 线 | 腾讯 `ifzq.gtimg.cn`（备源东财 `push2his`），**只对涨停/触板候选**（约 60~160 只）并发拉取 | 10 点前首触涨停、炸板回封 |
| 上证指数 | 腾讯 `sh000001`（备源东财 `stock/get`） | 首页大盘环境卡（实时点位/涨跌/涨跌家数/领涨板块） |
| **分时走势序列（v1.6）** | 每次快照按「交易分钟」落一帧（全市场 收盘价/成交额/均价线），当日缓冲 + 落盘 `data/cache/realtime_series.npz` | 5min 动量、加速度、均价线方向、量能脉冲、日内位置、相对大盘 → **走势分** |

**走势分（v1.6，仅盘中）**：由上面的分时序列计算 0~100 分（均值 50，只用当日数据）：

```
走势分 = 50 + 11·tanh(mom5/3) + 8·tanh(accel/1.2) + 10·tanh(均价线斜率/1.5)
        + 6·tanh(量能脉冲−1) + 8·(日内位置−0.5) + 6·tanh(相对大盘/4)
        − 7·[回撤>2% 且 mom5<0 且 放量]     # 冲高回落+放量 = 诱多/出货
```

它折算成 **±6 分**叠加在最终分上，**只影响同分区间的先后，不改任何策略判据**。
页面每行显示走势标签（加速上攻 / 均价线走强 / 走平 / 冲高回落 / 盘中转弱 + 5min 涨幅），
标题区标注数据源（腾讯行情 / 东财 push2）与走势样本分钟数。

> 走势分生效前提：当日**至少 2 帧**且间隔 ≥1 分钟。因为是手动刷新，帧是稀疏的——系统会用真实间隔做「按分钟折算」
> （例如两次刷新相隔 3 分钟，就把这段涨幅折到 5 分钟口径），所以**隔几分钟点一次刷新**就有走势分，不必恰好卡 5 分钟。

**可买性（盘中特有）**：涨停封板的股票买不到，因此每只票都带可买性标签，默认只显示「可买 / 临界」：

| 标签 | 判定 | 处理 |
|---|---|---|
| 可买 | 距涨停 >2% | 正常展示 |
| 临界 | 距涨停 ≤2% | 展示但提示（可能随时封板） |
| 已封板 | 现价 = 涨停价 | **默认过滤**，可在「全部（含已封板）」里查看 |
| 一字板 | 全天一字（无语义买点） | **默认过滤** |

页面顶部有「只看可买 / 全部（含已封板）」切换，并显示当日可买/已封板数量。

**静态刷新（v1.3）**：Realtime 刷新不再整页重建 —— 大盘卡只改文本节点、股票列表按 code 做 keyed diff，
刷新时**不闪白、不丢滚动位置**（实测 `#envCard` / `#stockList` DOM 节点复用、scrollTop 保持）。

**手动刷新（v1.5）**：已移除所有行情轮询（原 15~20s 定时器 / 页面可见性补刷 / 状态轮询）。
现在默认只在两种时机请求实时行情：① 打开或切换页面；② 点击右上角刷新按钮。
手动刷新会带 `?refresh=1` 打穿客户端与本地缓存；页面文案同步改为「点击右上角刷新」。

**不自动刷新（v1.6.1）**：**没有**任何行情轮询/定时刷新（自动刷新开关已移除）——只在「打开或切换页面」「点右上角刷新」时请求。
手工刷新每次 16 个请求（全市场 15 + 指数 1），把刷新当“手动采样”：两次刷新间隔 ≥1 分钟即可得到走势分。

**三类视图（v1.3）**：

| 区块 | 内容 | 说明 |
|---|---|---|
| 事件提醒 · 已封板 | `10点前首触涨停`、`炸板回封` | 这两类天然是封板状态 → 不占推荐位，只作打板/次日跟踪 |
| **回踩低吸型（置顶）** | 龙头回踩均价、站上分时均价，且当日涨幅 <7% | 优先展示，低吸类；≥7% 的划回突破组 |
| 突破型 | 放量突破、涨速异动、板块资金流（含 ≥7% 的强势票） | 强势突破类，注意「追高/高危」标签 |

**追高标记**：涨幅 ≥7% 标「追高」、≥9% 标「高危」（对应知识点-带柄茶杯「高于最佳买点 5~10% 不买」）。

### 评分规则（v1.4 → v1.6 五层）

**三层结构**（页面「评分规则 ›」弹层里也能看）：

| 层 | 规则 |
|---|---|
| ① 单策略打分 | 每条策略按知识点卡判据给 0~100 分，公式各不相同（见下） |
| ② 多策略聚合 | 命中多条时按权重加权平均（首触/杯柄 1.3，放量突破/RS 1.1~1.2，其余 1.0） |
| ③ 共振加成 + 预警折扣 | `最终分 = 0.9 × 加权均分 + min(24, (命中数−1)×8)`；命中「量价背离」预警再 ×0.75 |
| ④ 盘中走势融合（v1.6，仅实时源可用） | 走势分(0~100) 折算成 ±6 分加在③上；排序键 = (最终分, 走势分, 命中数) |
| ⑤ 可买性与分组 | 先剔除涨停封板/一字板 → 回踩低吸组置顶 → 追高/高危仅标注不扣分 |

盘中 8 条策略的原始分公式：

| 策略 | 公式 |
|---|---|
| 龙头回踩均价 | 40 + RS(0~16) + 贴线(0~14) + 回踩幅度(0~12) + 缩量(0~10) + 涨幅温和(0~6) + 均价线向上(0~5) − 5min加速下跌(0~6) |
| 站上分时均价 | 55 + 40×tanh(高于均价线幅度/5%) + 6×均价线向上 + 5×放量站上；均价线明显走低 ×0.9，已封板 ×0.75 |
| 盘中放量突破 | 60 + 30×tanh((量比−2)/6) + 10×tanh(5min涨速/3) + 6×走势动量 + 4×加速度；已封板 ×0.75 |
| 涨速异动 | 60 + 39×tanh(近 5 分钟涨速 / 4) |
| 板块资金流领涨 | 50 + 45×tanh(个股涨幅 / 8) |
| 尾盘强势 | 60 + 30×tanh(涨幅/8) + 9×tanh(涨速/3)；已封板 ×0.75 |
| 10点前首触涨停 | 95 − (首触时间−09:30 分钟数)×0.15（事件提醒用） |
| 炸板回封 | 85 固定（事件提醒用） |

> 注意：分数只在「同一时段、同一批候选」内可比，**不是收益率预测**；它表达的是「符合该知识点判据的程度」。

**降级策略**：实时源不可用（断网/非交易时段/接口变更）→ 自动回退到本地最近交易日分时回放，
页面明确标注「实时源暂不可用，已回退到 X 分时回放」，不会假装是实时。

| 配置项 | 默认 | 作用 |
|---|---|---|
| `REALTIME` | True | 盘中策略是否用实时行情（False = 只用本地回放） |
| `REALTIME_TTL` | 20 | 全市场快照缓存秒数（5min K 线固定 60s） |
| `STOCK_ADVICE_PUSH_QPS` | 8 | 每主机请求上限（令牌桶，突发 10）；调低更保守 |
| 环境变量 `STOCK_ADVICE_REALTIME=0` | — | 临时关闭实时（用于回退验证） |

> 打开页面后：顶部大盘卡显示「实时 HH:MM」，盘中页显示「● 实时行情 HH:MM:SS · 午后 · 腾讯行情 · 走势样本 N 分钟」。

### 自动刷新（v1.1）

服务启动后会跑一个后台看护线程，**你每天更新本地库后不需要重启服务**：

```
你更新 DuckDB（日终同步）
      │  ≤120s 内被发现（比较源库文件 mtime）
      ▼
等待源库静默 180s（避开你的同步任务，不抢锁）
      ▼
自动跑 ETL（约 25s，子进程）→ parquet 更新
      ▼
reset_ctx() 重载内存 → 重算推荐（约 2s）
      ▼
前端不轮询：下次打开/切页/点刷新时拿到的就是新数据
```

> 注意：这里「自动」指的是**服务端自动跑 ETL**，不是页面自动刷新；页面没有任何定时器（见上文 v1.6.1）。

- 状态胶囊显示：`● 数据 2026-10-19`；源库比缓存新时变黄：`⚠ 源库 2026-10-20 / 缓存 2026-10-19`；同步中变蓝。
- 手动入口：**⟳ 更新数据**（强制跑 ETL，约 25s）、**↻ 重算**（只重载缓存重算，秒级）。
- 你不希望它自动读 DuckDB（怕抢锁）：`config.AUTO_ETL = False`。
  之后你自己跑 `build_cache.py`，看护线程仍会发现 parquet 变化并**热重载**（不用重启）。
- 完全关闭看护：`python3 server.py --no-watch` 或 `config.AUTO_REFRESH = False`。
- 刷新间隔：`config.WATCH_INTERVAL`（默认 120s）；静默期：`config.ETL_QUIET_SECONDS`（默认 180s）。

| 配置项 | 默认 | 作用 |
|---|---|---|
| `AUTO_REFRESH` | True | 是否启动看护线程 |
| `WATCH_INTERVAL` | 120 | 轮询间隔（秒） |
| `AUTO_ETL` | True | 源库有新日期时是否自动跑 ETL |
| `ETL_QUIET_SECONDS` | 180 | 源库文件静默多久才读（避免抢锁） |

依赖：`flask`、`pandas`、`numpy`、`duckdb`、`pyarrow`（本机已装）。

## 三、界面（移动端 App）

> v2.0 起前端由 PC 网页重构为移动端 App：4 个底部 tab + 5 个详情屏，hash 路由（返回键/侧滑可退），
> 可安装为 PWA。截图见 `out/screens-app/`。

**信息架构**

```
推荐 (home) ──▶ 个股详情 (/stock/:code)
策略 (strategies) ──▶ 策略详情 (/strategy/:id) ──▶ 知识点卡 (/card/:name)
知识卡 (cards) ──▶ 卡片详情 (/card/:name)
手册 (playbook)
任一页 ──▶ 数据同步 sheet（重算 / 更新数据）
```

| 屏幕 | 路由 | 内容 |
|---|---|---|
| **推荐** | `#/home` | 大盘环境卡（闸门 + **上证指数今日涨跌** + 近 60 日走势 + 20 日/5 日 + 封板率/涨跌家数 + 领涨板块）→ 三时段分段 → 命中策略 chips → 个股榜（价格/涨跌/行业/命中数/评分） |
| **个股详情** | `#/stock/:code` | 大价格 + 40 日走势 + 命中依据（策略/评分/理由/触发条件）+ 风险预警 + 数据 |
| **策略库** | `#/strategies` | 27 条策略，按时段分段筛选；右侧直接给「今日命中」数量 |
| **策略详情** | `#/strategy/:id` | 执行口径 + 参数 chips + 知识点卡入口 + 今日命中个股 |
| **知识卡** | `#/cards` | 搜索（防抖）+ 时段分段 + 类型 chips + 仅看可执行 + 分页加载 |
| **卡片详情** | `#/card/:name` | Markdown 全文（标题/引用/列表/表格/双链跳转）+ 数值判据 + 来源 |
| **作战手册** | `#/playbook` | 《作战手册·诉求-01 选股》原文渲染（表格可横滑） |
| **数据同步** | bottom sheet | 源库/缓存/上次检查/自动 ETL 状态 + 重算（秒级）+ 更新数据（25~40s） |

**移动端访问**

```bash
# 1) 手机与电脑同一 Wi-Fi，让服务监听所有网卡
SAA_HOST=0.0.0.0 python3 server.py     # 本机 http://127.0.0.1:8770

# 2) 拿本机内网 IP
ipconfig getifaddr en0                 # 例如 192.168.1.7

# 3) 手机浏览器打开
#    http://192.168.1.7:8770
```

iOS Safari：分享 → 添加到主屏幕；Android Chrome：菜单 → 安装应用。
安装后全屏 standalone（无地址栏），状态栏黑底白字。

> **关于 HTTPS**：浏览器只在 `localhost` 或 `https` 下启用 service worker。
> 走内网 HTTP 时界面完全可用、iOS 也能「添加到主屏幕」，但**离线兜底不生效**（`sw.js` 静默跳过）。
> 要完整体验 PWA，用一条隧道即可：`cloudflared tunnel --url http://127.0.0.1:8770`，用它给出的 https 地址打开。

**数字口径**（避免"列表 30 / 详情 0"这类误读）

| 指标 | 定义 | 显示规则 |
|---|---|---|
| 策略「今日命中」 | 该策略当天命中的**个股数** | 引擎每策略最多产出 30 只，达到上限显示 `30+` |
| 策略详情「推荐榜」标记 | 这只命中股**同时进入了该时段 top20 个股推荐** | 未进榜 ≠ 没命中，只是综合评分未进前 20 |
| 个股「命中 N 条」 | 命中该股的**策略条数**（另一根轴） | 与上面两个数不可直接比较 |

> 历史问题 ①：首页曾把 **20 日累计涨跌**（-3.86%）放在主价格右侧、颜色也按 20 日算，
> 被读成"今天跌了 3.86%"（实际当日 +0.12%）。现在主位置固定为**今日涨跌**，20 日/5 日降到键值区，
> 走势线的颜色按区间涨跌并附「近 N 个交易日 xx%」标签，两处颜色各自有解释。
>
> 历史问题 ②：v2.0 早期版本的策略详情从「推荐榜 top20」反查命中，
> 导致 30 只命中的策略只要没进榜就显示 0 只。现已统一为「策略自身命中集合」，
> 列表与详情同源（`/api/strategies` 与 `/api/strategy/<sid>` 的计数完全一致）。

**首页大盘环境的口径**（每个数都能在「数据口径与自检」里查到来源）

| 数字 | 算法 | 口径 / 备注 |
|---|---|---|
| 上证 / 今日 | `index_daily` sh000001 收盘、收盘与前收 | 现算，不是外部给定 |
| 中期结构 | 收盘 vs MA20 vs MA60（MA 由收盘价现算） | 多头排列 / 空头排列 / 均线纠缠 + MA20 斜率 |
| 涨 / 跌家数 | 日线 `pct_chg` 全市场 | **不剔除**任何板块（含 ST、北交所） |
| 涨停 / 炸板 | 日线 `close` / `high` 对 `limit_price`，剔除 ST / 北交所 | 炸板 = 盘中触及涨停但收盘未封住 |
| 封板率 | **同一批股票内**：收盘封住 / 曾涨停 | 例：52 / 84 = 61.9%（是"封成率"，不是涨停占全市场） |
| 涨停占全市场 | 涨停家数 / 统计基数 | 例：52 / 5025 = 1.0%；曾涨停也仅 1.7% |

> ⚠️ **不能拿东财涨停池除以「涨停池+炸板池」**：炸板池包含「炸板后又回封」的个股
> （例如某股收在涨停价、仍被列入炸板池），与涨停池语义重叠；两池对 ST / 北交所的取舍
> 也与日线不同，分子分母不同源。历史上首页按池表算得 64.3%，已改为日线口径（61.9%）。
> 池表仍用于策略里的「涨停原因 / 连板标签」，不参与首页展示。

> ⚠️ **封板率 ≠ 涨停占比**。封板率的分母是「当日曾触及涨停的股票」，不是全市场：
> 10-20 全市场 5025 只里只有 84 只摸过涨停（1.7%）、52 只收盘封住（1.0%），
> 而"摸过涨停的 84 只里有 52 只封住"= 61.9%。这两个数完全不是一个量级，界面上已把两者并排标出。
>
> ⚠️ 「中期结构」是**趋势维度**，「今日 +0.12%」是**单日维度**，两者可以相反（弱反弹）。
> 卡片上会同时给出收盘/MA20/MA60 三个数，便于自己核对，而不是只给一个判断词。

**走势图的颜色规则**（首页大盘 / 个股详情共用）

多日走势线本身没有单一方向，所以**线条保持中性白**，不承载涨跌；
方向交给三处一致表达：**端点圆点（按今日涨跌上色）+ 昨收虚线（同色）+ 主价格**。
图下方caption 写明"今日 +0.12% · 虚线为昨收 3730.92"，因此不会出现"上证上涨但线条是绿的"这种矛盾。

> 历史问题：早期版本把线条颜色绑在「近 60 日区间涨跌」（-3.34% → 绿），
> 与主价格的「今日 +0.12%」颜色相反，看起来像数据错误。已改为中性线 + 端点/昨收线表意。

**实现说明**

- 前端零依赖：原生 HTML/CSS/JS + hash 路由 + 事件委托，无构建步骤；

  token 与组件规格见该目录 `tokens.json` / `README.md`，可据此增补表单、弹窗、空态等未覆盖组件。

## 六、知识卡 → 策略的判定规则

`ingest/build_cards.py`：

1. **选股范畴**（557 张）
   - 核心：卡片 `> 诉求：` 含 `诉求-01`（选股）
   - 补充：含 `诉求-02`（买入）且时段被判定为盘前/盘中
   - 环境：含 `诉求-07`（大盘择时）且标题是轮动/大盘/指数/环境/择时/情绪
2. **时段判定**（强信号优先）
   - 盘前强词：集合竞价 / 竞价 / 09:25 / 盘前 / 隔夜 / 首板次日 / 开盘区间
   - 盘中强词：分时 / 盘中 / 日内 / 涨速 / 量比 / 盘口 / 做T / 首触 / 封板 / 炸板 / 尾盘
   - 标题+一句话权重 5、弱词权重 2、正文权重 1；都不命中 → 盘后
3. **类型标签**：竞价 / 分时 / 涨停打板 / 量价 / 形态 / 均线 / 指标 / 资金 / 板块轮动 / 基本面 / 大盘择时 / 风控 / 方法统计
4. **数值判据**：正文里自动抽取 `≥18~20%`、`<6%`、`2 倍`、`5 日` 等阈值，展示在卡片上

5. 重跑 `build_registry.py` + 重启 server

## 八、局限与风险（务必阅读）

- **盘中已是实时，但不是交易终端**：快照来自东财公开接口（约 12s 延迟 + 15s 前端刷新），不保证撮合级实时；盘前/盘后仍基于日终数据。
- **实时源为公开接口**：可能限频/变更/断网，失败会自动回退本地回放并明确标注。
- **无回测**：策略参数取自知识卡原文与本机既有研究，但**本仓库不做收益回测**；
  按知识库自己的回测纪律（`bt_guard` / 样本外 ≥30 独立日），上线前必须补验证。
- **时点语义**：盘前推荐用上一交易日收盘数据生成，竞价类策略展示的是「最近一次竞价结构」，
  次日开盘需人工对照触发条件（页面已标注）。
- **数据口径**：日线来自前复权技术指标表（`tech_factor_qfq`），分钟为未复权原始价；
  跨日收益与价位过滤存在轻微前视（前复权因子随未来除权变化）。
- **过滤条件**：已剔除 ST / 退市 / 北交所 / 停牌 / 成交额 <3000 万 / 价格 <2 元；ST 历史不可得，仅按当前名称过滤。
- **风险提示**：本工具是「知识整理 + 规则筛选」，不构成投资建议。

## 公网访问（临时隧道）

服务默认只监听 127.0.0.1。需要在外网查看时，用临时隧道：

```bash
./tunnel.sh            # 打印一个 https://xxxx.lhr.life 地址
```

- **鉴权**：外网访问需要 Basic Auth，凭据在项目根目录 `.auth`（首次启动自动生成）；
  本机 `http://127.0.0.1:8770` 直连免登录。
- **域名会变**：隧道基于 localhost.run，每次重启地址不同；断开进程即关闭外网入口。
- **固定地址（推荐）**：用 Cloudflare Tunnel 绑定自有域名，详见 [`tunnel/README.md`](tunnel/README.md)。
  地址形如 `https://stock.你的域名.com`，永久固定、免费。
- **ngrok 说明**：免费版账号只有一个固定域名，若已被其它项目占用（例如 8767 端口的隧道），
  第二个 `ngrok http 8770` 会报 `ERR_NGROK_334`。要用 ngrok 需先停掉占用的隧道或升级套餐。
- **安全**：不要去掉 `.auth`；公网可点「刷新」会触发上游行情请求，务必保留鉴权。

### 导入后清理与防重（v1.7）

- **导入成功即删除上传副本**：该文件所有目标表都导入成功后，自动删除 `data/uploads/<批次>/` 里的副本；批次目录空了连目录一起删（`config.DELETE_AFTER_IMPORT`）。
- **防重校验**：按文件内容 SHA-256 记账（`data/uploads/ledger.json`）。重复上传同一文件时页面标「已导入过」并禁止勾选；
  如确需重导，勾选「允许重复导入」。服务端同样拦截（默认 `allow_duplicates=false`）。
- **手动清理**：右栏「最近上传批次」每条后面有 ✕，可删除该批次暂存文件（不影响已入库数据）。
